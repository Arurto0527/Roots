# shorts ── ショート動画「Rootsで英単語」を自動で作る道具

アプリ本体（index.html など）は**読むだけ**で、ここ（`/shorts`）の中だけで動きます。

## 使い方
```
python3 shorts/render.py --script shorts/scripts/001_port.txt --type 1 --number 1 --out 試作.mp4
python3 shorts/render.py --script 台本.txt --voice 録音.m4a --type 1 --number 2 --out 002.mp4
```
- `--voice` … 録音（m4a / mp3 / wav）。あると、録音の長さを各テロップの文字数で分けて、画面を声に合わせます。ないときは台本の秒数どおりの無音の仮動画になります
- `--preview フォルダ` … 各カットの静止画（PNG）と、カットの時間の表 `timing.txt` も書き出します（見た目の確認用）
- `--check` … 動画は作らず、文字のはみ出しチェックだけします（すぐ終わる。`--out` はいらない。`--preview` もいっしょに使えば静止画は出せる）
- `--report 一覧.json` … 全部の文字の位置（四すみの座標・大きさ）とチェック結果を書き出します
- `--sync chars|script|mix` … 録音の分け方。ふつうは `chars`（文字数の割合）。`script` は台本の目安秒数の割合、`mix` は両方の平均

## 録音と画面の合わせ方（`--voice` のとき）
1. 録音の長さを ffprobe で測り、各行の文字数の割合で「このへんで次の行」という見当をつけます
2. 録音の中の「間（0.2秒以上の無音）」を探し、見当に近くて長い間を区切りに選びます（行の途中の息つぎより、行と行の間のほうが長いので、ちゃんと行の間で切りかわります）
3. まとめ（summary・pairsum）は切り替えの0.2秒を除いて完全に3秒（カットは3.2秒）、カウントダウン（count）は3秒、声が短くても止めます。止めるぶんは録音に無音をはさむので、そのあとの声と画面はずれません
- **録音のコツ**: 1行読んだら、半拍（0.4秒くらい）あけて次の行を読む。これだけで画面と声がぴったり合います
- 間がほとんど見つからないときは ⚠ が出て、文字数の割合どおりに区切ります
- **録音のチェック（毎回自動）**: ファイルがない・音声が入っていないファイルなら止まります。音が小さすぎ（いちばん大きい所が -20dB より小さい）・音割れのおそれ・音が入っていない・最初や最後の無音が1.5秒より長い・動画が45秒をこえる／30秒より短い ときは ⚠ で知らせます。`--check` でも調べられます
- 試し: `python3 shorts/tools/make_test_voice.py 台本.txt にせ録音.wav breath` で、正しい区切りがわかっている「にせの録音」（ピー音）を作れます

## 文字のはみ出しチェック（毎回自動）
- 書いた文字の位置をすべて記録して、安全領域（上220px・下420px・右160px）・画面の左はし・文字どうしの重なりを調べます
- 安全領域に入りそうな文字は、その場で少しずつ小さくします（元の6割まで）。色分けした英単語は1語まとめて小さくします
- 枠（テロップの箱など）に入らない文は、ふつうの最小の大きさよりさらに小さくして入れ、「○px まで小さくしました」と ⚠ を出します。それでも入らなければ「台本を短くしてください」と出ます
- 右の安全領域の線から 12px 以内の文字も「近すぎます」と知らせます（文字・箱は線から24px離して置きます）
- 文字どうしは少しでも重なれば知らせます（大きな文字の p・g など下に伸びる部分が下の行にかかるのも見つけます）
- 最後に「文字の位置チェック: ○カット・文字 ○か所を調べて、問題 ○件」と出ます。問題が0件になるまで台本を直してください
- 出力: 1080×1920・30fps・H.264（veryfast・CRF 26）。最後に2秒のエンドカード「Rootsで英単語｜プロフのリンクから無料」が自動で付きます

必要なもの: Python 3、Pillow、cairosvg（`pip install cairosvg`。ピクトグラムを絵にする。ないと絵が出ず ⚠ が出ます）、budoux（`pip install budoux`。日本語を言葉の切れ目で改行する。なくても動きます）、ffmpeg、Noto Sans CJK フォント

## 台本の書き方（1行＝1テロップ＝1カット）
```
# 語根: port
[0.0-3.0] {hook} 英単語の覚え方、語源で一発
[5.5-8.5] {root port} port は「運ぶ」
[8.5-11.0] {kata ポーター porter port(運ぶ)+er(人)} 荷物を運ぶ人
[16.5-19.5] {word support} 下から運ぶ＝支える
[26.0-30.0] {summary} port＝運ぶ、で全部わかる
```
- `[開始-終了]` … 目安の秒数。`{ }` … そのカットの画面（場面）。`{ }` がなければ、ふつうのテロップ画面
- `#` で始まる行はメモ（`# 語根: port` は summary などで使います）
- 改行したいところに `\n` を書けます（「、」「。」のあとは自動で改行を試します。「／」のあとは、全体が1行に入らないときだけ改行します）
  - `\n` を書いた行は、書いたとおりの改行を優先します（`登る？降りる？\n語源で一発` は「？」のあとで切らず2行になる。入りきらないときだけ、今までどおり自動で切ります）
  - まとめ（summary のテロップ・pairsum の1行まとめ）では、英字のパーツのすぐあとに日本語の意味が続く所（`pot力`）に細い空白を自動で入れます（`pot 力`）。空白のせいで行が増える・文字が小さくなるときは入れません

| 場面 | 書き方 | 画面 |
|---|---|---|
| hook | `{hook}` / `{hook think}` | 大きな文字＋ルーツくん（normal / teach / think / cheer） |
| root | `{root port}` / `{root port=運ぶ}` / `{root bene=良く}` | 語根・意味・ピクトグラム（意味と絵はアプリのデータから）。bene のような接頭語は自動で青・「接頭語」になる（`{root bene=良く 接頭}` と書いてもよい）。絵がないときは枠を出さない |
| kata | `{kata カタカナ 英語 パーツ}` | カタカナ語→英語（語源の色分け）→分解 |
| word | `{word support}` / `{word export ex(外へ)+port(運ぶ)=輸出する}` / `{word malfunction 番号なし mal(悪く)+function(働き)=故障}` | アプリの単語データから：色分け・意味・英検級・ピクトグラム。**アプリにない語**は、単語のあとにパーツと `=意味` を書けば出せる（パーツの色と絵はアプリのデータから）。`番号なし` と書くと「受験単語 N」の札を出さず、番号も数えない（仲間として見せる語に） |
| summary | `{summary}` | ここまでに出た語根・カタカナ語・受験単語のまとめ（切り替えを除いて3秒以上止める）。root 場面を2つ以上出したときは「bene＝良く ＋ vol＝望む」のように全部を見出しにする。4つ以上なら語根だけを見出しにする |
| text | `{text}` | テロップだけ（ルーツくん） |

- trivia・origin・quiz・split・answer などの単語も、`{quiz benevolent bene(良く)+vol(望む)+ent(～な)=好意的な}` のようにパーツと意味を書ける。1回書けば、あとの場面は `{answer benevolent}` だけでよい
- **絵（ピクトグラム）の出し方**: 台本で書いた意味がアプリの絵の意味と合うときだけ、その絵を出します（in(中に) なら「中に」の絵。外へ／外に のような言い方の違いは同じとみなす）。合わないとき（dis(悪い) はアプリの絵が「離れて」用）は、まちがった絵を出さず、箱の中にパーツの文字を入れます（ℹ で知らせます。問題ではありません）
  - 自分で決めるとき: `dis(悪い|絵なし)`・`dis(悪い|絵あり)`、root 場面は `{root dis=悪い 接頭 絵なし}`・`{root dis=悪い 接頭 絵あり}`
- ex のあとの s は落ちるので（ex＋spect → expect）、残りの pect を語根の色にします
- 動画だけで絵を変えたいときは `data/picto_override.json` に書きます（今は pan の絵だけ。アプリの絵は変わりません）
- まとめの見出しは、台本で出した順ではなく単語の並び（dis ＋ aster）になります。1つの単語に全部入っていなければ 接頭→語根→接尾 の順です
- 左上の「Roots #連番」は、エンドカードには出しません（エンドカードは名前と案内だけ）
- 単語のあとに表情（normal / teach / think / cheer）を書くと、ルーツくんの表情が変わる（例 `{trivia danger cheer}`）

### 型②雑学（意外な語源）
| 場面 | 書き方 | 画面 |
|---|---|---|
| trivia | `{trivia danger}` | 「意外な語源」＋単語を大きく＋今の意味＋ルーツくん |
| origin | `{origin danger}` | もともとの意味（語源パーツの色分け・ピクトグラム） |
| reveal | `{reveal danger}` | 「むかし（語根の意味）」▼「いま（今の意味）」 |

### 型③推理（カウントダウン→分解→正解）
| 場面 | 書き方 | 画面 |
|---|---|---|
| quiz | `{quiz interrupt}` | 単語だけ（色なし）＋「この意味、わかる？」 |
| count | `{count interrupt}` | 3・2・1 のカウントダウン（2と1は必ず1秒ずつ。3秒より短いと3秒にのばす。3秒より長いときは、のびた分だけ最初の「3」を長く出す） |
| split | `{split interrupt}` | 分解（色分け＋パーツの絵と意味） |
| answer | `{answer interrupt}` | 「正解」＋意味・英検級・パーツ |

### 型④ペア（左右で比べる）
| 場面 | 書き方 | 画面 |
|---|---|---|
| pair | `{pair precede proceed}` | 左右に2語。パーツの絵と意味、下に今の意味 |
| pairsum | `{pairsum}` | 2語の一覧＋テロップの文を大きく（1行まとめ。3秒以上止める） |

試作の台本: `scripts/001_port.txt`（①）・`002_danger.txt`（②）・`003_interrupt.txt`（③）・`004_precede_proceed.txt`（④）

動画をコミットする前に `python3 shorts/tools/check_samples.py` を実行します（`samples/` の動画が再生できるか調べます。NG が出たら作り直す）。

まとめの「受験単語」欄の名前は `{summary 欄=今日の単語}` で変えられます（受験向けでない語の回に）。

## データの作り直し（アプリの単語が増えたとき）
```
cd shorts/tools && npm install && node extract_assets.js
```
index.html から `shorts/data/words.json`（単語・意味・語源パーツ・色の種類）と `shorts/data/picto.json`（ピクトグラム）を作り直します。
色はアプリと同じ（接頭 #2F5D9E・語根 #B5652B・接尾 #4F7A5E、アクセント紫 #534AB7）。
