# Roots 単語データ仕様 v3（2026-09-10 改訂）

単語データを作成・差し替えるときは、この仕様に従う。
アプリ本体は `roots_v3.html`（現在のファイル名は `index.html`）。データブロックを差し替えるだけで動く（アプリ側の変更は不要）。

**方針: 語源への着目を最優先する。** 語源から離れる要素は原則載せない。

---

## 0. アプリ側の前提（データ作成者が知っておくべき点）

アプリは **1枚あたり2タップ**（カードをタップ → 「もう一度」か「覚えた」）で回る。
同じデータを**4つの向き**で出題する。

| 出題の向き | 出題面に出るもの | 答え合わせ面 |
|---|---|---|
| ① 単語 英→日 | `word` / `pronunciation` / 発音ボタン | 全情報 |
| ② 単語 日→英 | `meaning` / `partOfSpeech` / 文字数 / 頭文字 | 全情報 |
| ③ 用例 英→日 | `example`（見出し語を色分け）/ 発音ボタン | 全情報 |
| ④ 用例 日→英 | `exampleJa` ＋ 見出し語を空所にした `example` | 全情報 |

答え合わせ面は**スクロールしない**。単語・意味・語源チップ・イメージ文・例文2本・関連語4語を
1画面に収め、収まらないときだけ自動で縮む（下限 68%、余裕があれば最大 120% まで拡大）。

---

## 1. 対象範囲

この仕様書は**単語を追加するたびに毎回使う**。特定の番号や特定の回を前提にしない。

- 単語は **単語帳『LEAP』の見出し語**を使う。**見出し語（英単語）だけを使い、LEAP の語義・例文・語法解説は写さない。** 意味・例文・語源はすべて新規に書き起こす。
- **すでにアプリに入っている語は再生成しない。** 綴り・語根は既存データに合わせる。
- id は**既存の本編の続き番号**から始め、欠番・重複を作らない（アプリの範囲指定が id の連続を前提にしている）。
- **`part` は10語ごとに1つ。** 本編の先頭から数えて 1〜10 が `part: 1`、11〜20 が `part: 2`、以下同様。
  追加する語の `part` は「その語の id ÷ 10 の切り上げ」で機械的に決まる。
- 1回の追加語数は **10の倍数**にする（パートが半端にならないようにするため）。

### Part α（管理者テスト用）— 常に末尾

アプリには **Part α という管理者テスト用の単語群**がある。

- **α は必ず全単語の一番うしろに置く。** 本編の語を追加するたびに α の id を後ろへずらし、
  常に末尾に来るようにする
- α を削除しない・本編に混ぜない・α の中身を書き換えない
- α の `part` は本編のパート番号の続きにする（本編が10パートなら α は `part: 11` 相当）
- 学習記録は見出し語にひも付いているので、id を変えても記録は消えない

LEAP の語は基本語に見えてもラテン語由来が多く、**大半は語源分解できる**。「単語が高校生向けでない」という指摘は不要。

## 2. データ構造と、アプリが自動で読む箇所

```js
{
  id: 11,
  word: "explain",
  partOfSpeech: "他動詞",              // §2-4 の語彙から選ぶ
  meaning: "説明する",                  // 複数語義は「；」区切り。先頭が主要語義
  pronunciation: "/ɪkˈspleɪn/",        // IPA
  part: 2,                             // 10語ごとに1つ（id 11〜20 なら 2）

  // 例文は2文。用法を変える（§3）。用例出題に使われる（§2-3）
  example:    "She explained the rule to the new members.",
  exampleJa:  "彼女は新入部員にその規則を説明した。",
  example2:   "Can you explain why you were late?",
  exampleJa2: "なぜ遅刻したのか説明してくれますか。",

  // 出題面の「語源のヒント」。答えを言わず「…？」で終える。→ は1回だけ
  etymologyProcess:    "ex（外へ）＋ plain（平らにする）→ でこぼこを外に…？",

  // 答え合わせ面の結論。「＝意味」で締める。→ は1回だけ
  etymologyConclusion: "ex（外へ）＋ plain（平らにする）→ ややこしい話を平らにならして外に出す＝説明する",

  hook: "…",                           // 任意。語源で分解できない語だけ（§4-2）

  relatedWords: [                      // 原則4語。breakdown 必須（§4-1）
    { word:"plain",   meaning:"平らな；わかりやすい", breakdown:"plain（平らにする）→ でこぼこがなく、そのまま見通せる" },
    { word:"plane",   meaning:"平面；飛行機",         breakdown:"plane（平らにする）→ 平らな面。翼の平らな面から飛行機" },
    { word:"explore", meaning:"探検する",             breakdown:"ex（外へ）＋ plore（叫ぶ）→ 外へ声を上げながら未知へ踏み込む" },
    // 語根が共通でない語を載せるときだけ synonym:true（§4-1-b）
    { synonym:true, word:"describe", meaning:"描写する", breakdown:"どんなものかを言葉で写し取る。explain は理由や仕組みを解く" }
  ]
}
```

`example2` / `exampleJa2` / `hook` は任意。無ければそのぶんが表示されないだけ。
**同意語だけを集めた独立セクションは作らない。** 同意語は §4-1-b の例外扱いのみ。

### 2-1. 語源チップの自動分解 ← `etymologyConclusion`

アプリは `etymologyConclusion` の **最初の `→` より左**を `＋` / `+` で分割し、
各断片を `語根（意味）` の形として読み、色付きチップに変換する。

**したがって必ず守ること:**

- 左半分は **`語根（意味）` の並びだけ**にする。余計な語や説明を混ぜない
- 語根は **ラテン文字のみ**。かな・漢字を含む断片はチップにならない（読み飛ばされる）
- 語根は **14文字以内**
- **`→` は語全体で1回だけ。** 2回以上書くと、2つ目以降がイメージ文に紛れ込む
- 全角 `＋` と半角 `+` のどちらでも動くが、**`＋` に統一**する

```
OK   ex（外へ）＋ plain（平らにする）→ …＝説明する
NG   「ex（外へ）」と「plain（平らにする）」から → …     ← 括弧の外に余計な文字
NG   ex（外へ）＋ plain（平らにする）→ 平らにする → 説明する  ← → が2回
```

分解できない語（`tip` など）は1つだけ書く: `tip（細く尖った先）→ …＝ちょっとした助言`

> 自動分解がどうしても効かない語だけ、`roots: [{morph:"ex", gloss:"外へ"}, ...]` を書けば
> そちらが優先される。通常は書かなくてよい。

### 2-2. 語根マップに載る条件 ← `relatedWords[].breakdown`

語根マップ画面は、**見出し語の語源に加えて、関連語の `breakdown` からも語根を抽出**し、
2語以上に共通する語根を横断表示する。抽出ルールは §2-1 と同じ。

**したがって `breakdown` は必ず `語根（意味）＋ 語根（意味）→ イメージ` の順で書き出す。**

```
OK   pos（置く）＋ ion（名詞）→ 置かれている場所
NG   「置く」から。posit が語根 → 置かれている場所      ← 先頭が語根（意味）でない
```

`synonym:true` の語は語根マップの対象外なので、自由な日本語で書いてよい。

**語根の綴りは統一する。** 綴りが揺れると同じ語根が別項目に分かれ、マップの価値が落ちる。

| 統一形 | 使わない綴り |
|---|---|
| `pos`（置く） | ~~`posit`~~ |
| `grat`（心地よい） | ~~`gree`~~ ~~`grac`~~ |
| `ad`（〜へ） | ~~`a`~~ |

なお `ion` `ment` `ful` `able` などの文法的接尾辞は、`breakdown` に書いてよいが
語根マップには出ない（アプリ側で除外している）。

### 2-3. 用例出題で使われる条件 ← `example` / `exampleJa`

**③ 用例 英→日** は `example`（1文目）をそのまま出す。見出し語は色分け表示される。

**④ 用例 日→英** は、例文から見出し語を探して空所にし、和訳と一緒に出す。
検出できる形は **原形 / 語尾の e を取った語幹 ＋ `s, es, d, ed, ing, ies, ied`** のいずれか。

- **2文のうち最低1文は、この検出に引っかかる形で見出し語を含める**
  （引っかからないと ④ が出題されず、その語は3方向でしか回らない）
- 不規則変化（`bring → brought`、`think → thought` など）は検出できない。
  その場合は**もう1文を原形または規則変化で書く**
- 見出し語に**空白が含まれる語（句動詞・熟語）は ④ の対象外**になる。それ自体は問題ない
- **1文目は空所補充として成立する文にする。** 前後の文脈だけで語を絞り込めること。
  `He ___ it.` のような手がかりのない文にしない
- 和訳は、空所に入る語に対応する日本語がはっきり出ている文にする
  （④ では和訳が唯一の手がかりになるため）

### 2-4. 「日→英」出題で使われる条件 ← `meaning` / `partOfSpeech`

**② 単語 日→英** は `meaning` だけを大きく見せ、補助として `partOfSpeech` ・ 文字数 ・ 頭文字を出す。

- **`meaning` から、その英単語が一意に思い浮かぶこと。**
  語義が他の語と丸かぶりだと、正しく思い出しても「違う語」に見えてしまう
  - 失敗例: `argue`「主張する；言い争う」と `claim`「主張する；要求する」（どちらも先頭が「主張する」）
  - 対処: 先頭の語義をずらす。`argue`「言い争う；根拠を挙げて主張する」/ `claim`「（当然の権利として）要求する；主張する」
- `partOfSpeech` は次の語彙から選ぶ（表記ゆれがあるとヒントとして機能しない）:
  **`名詞` / `他動詞` / `自動詞` / `他動詞・自動詞` / `形容詞` / `副詞` / `前置詞` / `熟語`**

### 2-5. ヒントの伏せ字について

「語源のヒント」は出題面で最初から押せる。**日→英の向き（② ④）では語根チップを出さず、
`etymologyProcess` の後半だけ**を見せる（チップが答えの綴りをそのまま出してしまうため）。

- したがって **`etymologyProcess` の `→` より右は、それ単体で手がかりになる日本語**にする。
  「心地よいほうへ…？」のように、意味の方向が伝わる書き方にする

## 3. 例文の書き方

同じ形の文を2つ並べない。**用法を変える**こと。

| 変化のさせ方 | 例 |
|---|---|
| 態を変える | 能動 ↔ 受動 |
| 時制・法を変える | 過去 ↔ 未来・仮定（may / if） |
| 構文を変える | 他動詞＋目的語 ↔ that節・to不定詞・自動詞 |
| 場面を変える | 硬い場面（会議・契約）↔ 高校生に身近な場面（学校・部活） |

- **2文目は高校生の生活に寄せる**（学校・部活・友人・受験）と定着しやすい
- 1文は **8〜14語程度**。長すぎると用例出題で読み切れない
- 和訳は直訳寄りにし、**見出し語に対応する日本語が `meaning` の先頭語義とそろう**ようにする
  （アプリが和訳中のその語を自動で太字にするため）

## 4. relatedWords と hook の品質基準 — 最重要

### 4-1-a. 原則（同じ語根の語）

**旧データの最大の問題は、語根と単語のつながりが弱かったこと。** 1語ずつ次を満たすこと。

- **語根が本当に共有されているか確認する。** 見た目が似ているだけの語を入れない
  - 失敗例: `disagree` の breakdown が `dis（否定）＋ agree（心地よい）` になっている。
    `agree` は語根ではない。正しくは `dis（否定）＋ grat（心地よい）`
- **`breakdown` を必ず書く。羅列にしない。** §2-2 の形式で、比喩を1つ入れて情景が浮かぶようにする
- **CEFR B2以下のやさしい語を優先する。** 読み手は高校生。難語を関連語に置いても手がかりにならない。
  `ferry`（フェリー）`prefer`（より好む）のように、既に知っている語で語根を体感させる
- 4語のうち**最低2語は中学〜高校基礎レベル**（A2〜B1）にする
- **LEAP 収録語を優先的に混ぜる。** 1語覚えると別の番号の語が半分わかる状態になる。重複例:

| 語根 | LEAP での重複 |
|---|---|
| grat（心地よい） | agree(1) / grateful(13) / congratulate(17) |
| press（押す） | impress(19) / express(24) |
| form（形） | information(26) / form(46) |

### 4-1-b. 例外（同じ語根の語が存在しない場合）

同じ語根を持つ語がどうしても見つからない語（`tip` `blame` など）に限り、意味の近い語を載せてよい。

- そのエントリに **`synonym: true` を立てる**
- 見出しはアプリが自動で切り替える（語根の語が1つでもあれば「同じ語根の語」、全部が同意語なら「意味の近い語」）
- 同意語でも `breakdown` は必須。**その語自身の成り立ちか、見出し語との使い分け**を書く
- **語根の語と同意語を混ぜてよい。** 例: `discuss` は discussion / percussion（語根）＋ debate / argue（同意語）

### 4-2. hook（覚え方の一言メモ）

**語源で分解できない語には `hook` を書く。** 語源が弱い語ほど記憶の取っかかりがない。

| 種類 | 例 |
|---|---|
| 語法・型 | `blame A for B（Bのことで A を責める）の形で覚える。be to blame なら「責任がある」。` |
| 日本語で通じるイメージ | `日本語の「チップ」「ペン先」がそのまま使える。どれも全体ではなく先っぽの話。` |
| 複数の意味をつなぐ核 | 多義語で、意味どうしが1つのイメージから出ていることを示す |

- **1行・60字以内**
- 語源がしっかりある語には**書かない**。全語に付けると語源への集中が薄れる

### 4-3. why（なぜこの意味になったか）

**語根の意味から、単語の意味が離れている語だけに書く。** 学習者の「なぜ？」に答えるための項目。

答え合わせ画面には出ない。語源チップの下に出る「なぜこの意味？」ボタンを押すと、
語根コラムと同じ形の別画面で開く。そのため長さの制限はゆるいが、**120〜200字**に収める。

**`hook` と同じ内容を書かない。** 答え合わせ画面の `hook` と why を両方読むと、同じ文を2回読むことになる。
`node check-all.js` が重なりを見つけて NG にする。

書き方は語根コラム（`ROOT_NOTES`）にそろえる。行は `\n` で区切る。

| 見出し | 書くこと |
|---|---|
| 【なぜ】 | もとの語の意味と、そこから今の意味へどう移ったか |
| 【つながり】 | 同じ family の語、日本語のカタカナ語、使い分けの注意 |

```js
why:"【なぜ】apo（離れて）＋ log（言葉）で、もとは「一歩下がって事情を述べる」＝弁明。…\n【つながり】だから apology には今も「弁明」の意味が残っています。"
```

**3つの型に仕分けてから書く。**

| 型 | 見分け方 | 書くもの |
|---|---|---|
| ① 直結 | `etymologyConclusion` だけで意味まで届く（export, oppose） | 何も足さない |
| ② ずれ | 語根から意味までに飛躍がある（apologize, condition, electric） | **`why` を書く** |
| ③ 分解不可 | そもそも語源で割れない（tip, skill） | `hook` を書く |

- **①に `why` を付けない。** 全語に付けると「語源で分かる」という手ごたえが薄れる
- `hook` と `why` は両方あってもよい（役割が違う）

## 5. 文字数の目安

答え合わせ面は1画面に収める設計。収まらないと自動縮小がかかって文字が小さくなるので、次を守る。

| 項目 | 目安 |
|---|---|
| `etymologyConclusion` の `→` より右（イメージ文） | **50字以内**。答え合わせ面で一番大きく出る |
| `etymologyProcess` の `→` より右 | **30字以内**。「…？」で終える。日→英ではここだけがヒントになる |
| `relatedWords[].breakdown` | **45字以内** |
| `hook` | **60字以内** |
| `why` | **120〜200字**。`hook` と内容が重ならないこと |
| `relatedWords` の数 | **4語**（3〜4語。5語以上にしない） |
| 例文1文 | 8〜14語 |

## 6. 既存データで使用済みの語根

新規データはこの綴り・語義に合わせる。ここに載っている語根を再利用すると語根マップが育つ。

| 語根 | 意味 | すでに登場している語 |
|---|---|---|
| fer | 運ぶ | offer, ferry, transfer, prefer, suffer |
| vis | 見る | advise, visible, vision, revise, supervise |
| claim | 叫ぶ | claim, exclaim, proclaim, reclaim |
| pos | 置く | oppose, propose, compose, position, opposite |
| grat | 心地よい | agree, grateful, congratulate, grace |
| cuss | 打つ | discuss, percussion |
| plain | 胸を叩く／平らにする | complain |
| arg | 白く光らせる | argue |
| tip | 細く尖った先 | tip |

**接頭辞・接尾辞（既出）:**
`ad`（〜へ）/ `com`・`con`（共に・強く）/ `dis`（否定・バラバラに）/ `ex`（外へ）/ `op`（向かい合って）/

`ible`・`able`（できる）/ `ate`（動詞）/ `ry`（もの）

## 8. 出力前のセルフチェック（10語ごとに必ず実行）

出力する前に、10語すべてについて次を1項目ずつ確認し、**チェック結果を短く報告する**こと。

1. `etymologyConclusion` の `→` は **1語につき1回だけ**か
2. `→` より左は **`語根（意味）` の並びだけ**で、括弧の外に余計な文字がないか
3. `→` より右は **`＝意味` で終わって**いて、50字以内か
4. `etymologyProcess` の `→` より右は、**それ単体で手がかりになる日本語**で「…？」で終わっているか
5. すべての `breakdown` が **`語根（意味）` で書き出されて**いるか（`synonym:true` を除く）
6. 語根の綴りが **§2-2 の統一形・§6 の既出綴り**と一致しているか
7. `relatedWords` 4語のうち **2語以上が中学〜高校基礎レベル**か。難語ばかりになっていないか
8. 例文2文の **用法が違う**か（態・時制・構文・場面のどれかが変わっているか）
9. 2文のうち**最低1文が、原形または規則変化（s/es/d/ed/ing/ies/ied）で見出し語を含む**か
10. 1文目が**空所補充として成立する**か（前後の文脈だけで語を絞り込めるか）
11. `meaning` が **他の語と紛れない**か（先頭語義が他語と丸かぶりしていないか）
12. `id` が既存の続きから連番で、欠番・重複がないか。`part` が「id ÷ 10 の切り上げ」通りか
13. 語源で分解できない語にだけ `hook` があるか
13-b. **語根から意味が離れている語（②型）に `why` があるか。**直結する語に付けていないか
14. **Part α が全単語の末尾にあるか。** α の中身が書き換わっていないか

## 9. 納品と差し込み

1. 各回の出力を1つのテキストファイルに順番に貼りためる
2. 全語そろったら、アプリの `単語データ  ここから` 〜 `単語データ  ここまで` の間を丸ごと差し替える

**アプリ側の変更は不要。** パート一覧・範囲指定の上限・バッジやレベルの閾値は、
すべて総語数から自動計算される。
