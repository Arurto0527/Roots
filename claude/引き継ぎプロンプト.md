## このアプリの番号の決まり（毎回これに従う）

- **アプリの No.n ＝ LEAP の No.n。** 単語は `claude/leap-word-list.md` の**番号順にそのまま**足していく。
  並べ替えたり、飛ばしたり、好きな語を選んだりしない
- **Part α（管理者テスト用）は、常に全単語のいちばん後ろ。**
  本編を N 語足したら、α の id を N だけ後ろへずらす。**α の中身は書き換えない・消さない・本編に混ぜない**
- 本編の id は連番。欠番・重複を作らない
- `part` は「id ÷ 10 の切り上げ」

## いちばん最初にやること

```bash
node check-all.js
```

これで**今の状態と、今回使う値**が全部出ます。出力の最後にある
「次に N 語を足すときの値」に、この回で使う番号・`ALPHA_FROM`・`WORDS_LAYOUT`・
○×の保存キー・`sw.js` の `VERSION` が書いてあるので、**N に今回の語数を入れて使ってください。**

そのうえで、これから追加する範囲を声に出して確認してください。

> 「本編の続きは No.◯◯ から。今回 ［N］語なので No.◯◯〜No.△△。
> 　`claude/leap-word-list.md` を見ると、その範囲は ◯◯ / ◯◯ / ◯◯ … です。
> 　Part α は No.□□〜□□ から No.■■〜■■ へ動かします。」

ここがずれていると全部やり直しになるので、**先にユーザーに確認を取ってから**着手してください。

## 手順0. 先に「終わったと言える条件」を確認する

**この作業は「単語データを書く」だけでは終わりません。** 下の7つが全部そろって初めて完了です。
過去に、単語データだけ入れてピクトグラム・語源コラム・英検レベルが抜けたまま
「完了」と報告してしまい、あとから100語ぶんまとめて直す羽目になりました。同じことを繰り返さないでください。

1. 単語データ（`node validate.js` が ALL PASS）
2. 新しく増えた語根ぜんぶに **ピクトグラム**（`PICTO_ROOT`）
3. 新しく増えた語根ぜんぶに **語源コラム**（`ROOT_NOTES`）
4. 追加した語ぜんぶに **英検レベル**（`EIKEN_LEVELS`）
5. 新しい英文ぜんぶの **発音音声**（米・英）と `roots-audio-index` の作り直し
6. 番号まわりの手当て（α の移動 / `ALPHA_FROM` / `WORDS_LAYOUT` / 番号の読み替え / `sw.js` の `VERSION`）
7. 使わなくなった音声ファイルの削除

最後に `node check-all.js` が **NG 0件**になれば、1〜7 はそろっています。

## 手順1. 単語データを10語ずつ書く

作業用ファイル `words_<開始番号>-<終了番号>.js` を作り、**10語ずつ**書き足す。
（直前の回のファイル、たとえば `words_251-350.js` が見本。キーの順序・インデントをそろえる）

- **見出し語（英単語）と並び順だけを LEAP から取る。** LEAP の語義・例文・語法解説は写さない。
  意味・例文・語源はすべて新規に書き起こす
- 1語のデータの形・文字数の上限は `claude/word-data-spec.md` の §2〜§5 のとおり

10語書くごとに、必ず次の**3回のチェック**を通してから次の10語へ進む。

1. **機械チェック**: `node validate.js --add <作業用ファイル>`
   → `ALL PASS` になるまで直す。**警告も可能な限り消す**
   （とくに「語源で分解できる語に hook がある」。hook は分解できない語だけ）
2. **読み直し**: 自分で語源・例文・和訳を声に出すつもりで読み返す
3. **第三者チェック**: サブエージェント（Task / Agent）に、仕様書とその10語だけを渡して点検させる
   - 語源の説明が言語学的に正しいか（でたらめな分解になっていないか）
   - `relatedWords` が本当にその語根を共有しているか。同じ語根の綴り・訳語が割れていないか
   - 例文の英語が自然・文法的に正しいか、和訳が正確で自然な日本語か
   - `meaning` の先頭語義・`meanings[0]`・`partOfSpeech` と例文の用法がそろっているか
   → 指摘は必ず反映してから次へ

**10語ごとに必ず見る追加項目**（過去に見落としたところ）

- **見出し語の重複**: 追加する語が既存の本編にすでに無いか
  （過去に `vocabulary` を No.42 と No.348 に二重登録してしまいました）
- **`meaning` の重複**: 先頭語義が既存の語と丸かぶりしていないか
  （`explain` と `describe` が両方「～を説明する」になっていて、日→英が解けなくなりました）
- **例文の語数**: 1文 8〜14語。7語だと不合格です
- **`partOfSpeech`**: 許可された8種類だけ（`自動詞・他動詞` は不可。`他動詞・自動詞` が正）
- **語根の綴り**: `pos`（`posit` 不可）/ `grat`（`gree` `grac` 不可）/ `ad`（`a` 不可）

## 手順2. `index.html` に差し込む

N = 今回追加した語数。値は `node check-all.js` の「次に N 語を足すときの値」を見ること。

1. **Part α の id を N だけ後ろへずらす**
   （`{id:351,word:"hand in"` のように `{id:数字,word:"見出し語"` を1件ずつ置換。**α の中身は変えない**）
2. 新しい語を `RAW_WORDS` の**末尾**に足す（直前の要素の後ろのカンマを忘れない）
3. `const ALPHA_FROM=…;` を「元の値 ＋ N」に直す
4. `const WORDS_LAYOUT=…;` を1つ上げる。上のコメントに、その版で何をしたかを1行足す
5. **学習記録の引き継ぎ**（ここを忘れると生徒の○×が消えます）
   - `const v<前の版>IdToNew=id=>id>=<元のALPHA_FROM>?id+N:id;` を足し、既存の読み替え関数をこれに通す
   - `roots.listRecall.v<前の版>` を1つ上げ、前の版から読み替えて移す処理を足す
     （`index.html` の中にある、ひとつ前の版の移行処理がそのまま見本になります）
6. `node validate.js` が **全語 ALL PASS** になることを確認

## 手順3. ピクトグラムと語源コラムを足す（**ここが一番よく抜けます**）

まず「どの語根が足りないか」を機械で洗い出す。目視で探さないこと。

```bash
node check-all.js
```

「語源コラムが無い語根」「ピクトグラムが無い語根」「絵が1つも出ない単語」に出たものを、
ぜんぶ `ROOT_NOTES` と `PICTO_ROOT` に足す。

- `ROOT_NOTES` は既存と同じ形。`title` ＋ `body` は【なぜ】【身近な日本語／英語】【覚え方】の3段、本文120〜180字
- `PICTO_ROOT` は 48×48 の viewBox・線画のみ（`fill="none" stroke="currentColor"`）。
  意味が近い語根は、ファイル冒頭の `G`（共通図形）を使い回してよい
- `ature` `tude` `istic` `ture` `ior` のような**文法的な語尾は作らなくてよい**
  （`check-all.js` の `SUFFIX_EXTRA` で除外済み。新しくこの手の語尾が出て NG になったら、
  「本当に語根ではないか」を確かめたうえで `SUFFIX_EXTRA` に足す）
- **単語1語につき最低1つ、語根の絵が出ること。**
  `Pictogram` は語根の絵が0個だと何も表示しません。
  1語しかない morph が語尾扱いで絵が出ない場合は、`PICTO_BY_GLOSS` に
  `"語根|意味"` のキーで足すと、その語だけに絵を出せます（例: `"age|生きてきた時間"`）。
  `PICTO_ROOT` に足してしまうと、同じ綴りの語尾を持つ他の語（damage の -age など）にも
  誤って絵が出るので注意
- 新しい別綴りが出たら `ROOT_ALIAS` でまとめる

**ピクトグラムは必ず目で見て確認する。** コードを書いただけで終わりにしないこと。

```bash
node preview-picto.js man prov creat          # 語根を指定して並べる
node preview-picto.js --since "今回のコメント"  # 追加したコメント以降をまとめて
qlmanage -t -s 1000 -o /tmp /tmp/roots-picto.svg
# → /tmp/roots-picto.svg.png を画像として読む（ブラウザで /tmp/roots-picto.svg を開いてもよい）
```

見て「何の絵か分からない」ものは描き直すこと。過去に、手を描いたつもりが線が交差して
読めない絵になったり、「耐える」の絵が首吊りに見えたりしました。

## 手順5. 音声を作る

音声ツールは `/Users/arutokamiya/Documents/Roots単語アプリ/音声ツール`（`venv/bin/python` を使う）。

- 読ませる英文 = `RAW_WORDS` の `word` / `example` / `example2` / `relatedWords[].word`（前後の空白を除く）
- ファイル名 = その英文の **FNV-1a 32bit ハッシュ**（`charCodeAt` で計算）を8桁の16進数にしたもの。
  `index.html` の `clipHash()` と同じ計算にすること
- 声のモデル: 米 `en_US-lessac-high` / 英 `en_GB-cori-high`（`音声ツール/models/` にある）
- **`espeak_data_dir` には `/private/tmp/roots-espeak/espeak-ng-data` を渡す。**
  piper パッケージに同梱されている `espeak-ng-data` は中身が足りず、`phontab がない` というエラーで落ちます。
  もしそこに無かったら、`phontab` を含む完全な espeak-ng-data をそこへ置いてから実行してください
- 速さ: 単語（3語以下）は `length_scale=1.18`、文は `1.05`
- wav で作って `afconvert -f m4af -d aac@22050 -b 64000 -c 1 入力.wav 出力.m4a` で m4a にする
- 保存先は `audio/us/<ハッシュ>.m4a` と `audio/uk/<ハッシュ>.m4a`
- **すでにあるファイルは作り直さない**（存在チェックしてスキップ）
- 目安: 100語で新しい音声は 500〜600文 × 2（米英）。20〜30分かかります

## 手順6. 使わなくなった音声を消して、索引を作り直す

例文を書き直すと古い音声が残ります。`node check-all.js` の「使われていない音声」に出たものを `git rm` する。

**ただし次の4本は消さないこと。** 単語データには出てこないが、
アクセント切り替えの見本としてアプリが再生しています。

- `Hello. This is American English.` → `2d8379ef`（us / uk）
- `Hello. This is British English.` → `f36af822`（us / uk）

（`check-all.js` はこの4本を「必要なファイル」に含めているので、そのまま使えば消えません）

そのあと `<script type="application/json" id="roots-audio-index">` を
`audio/us` `audio/uk` のファイル名一覧から作り直して差し替える。
最後に `node check-all.js` の「音声の欠け」が0件になることを確認する。

## やってはいけないこと

- `audio/` の中身と `<script id="roots-audio-index">` の中身を context に読み込む（巨大です）
- Part α の中身を書き換える／消す／本編に混ぜる。**α は常に全単語の末尾**
- LEAP の番号順を変える／飛ばす／好きな語を選ぶ
- 既存の本編の語を作り直す（綴り・語根は既存データに合わせる）
- 学習データ（localStorage）のキーや形式を、読み替えなしで変える
- ユーザーの代わりにログインする
- 単語データだけ入れて「完了」と報告する（上の完了チェック表を必ず埋める）
