## 手順3. ピクトグラムと語源コラムを足す（**ここが一番よく抜けます**）


「語源コラムが無い語根」「ピクトグラムが無い語根」「絵が1つも出ない単語」に出たものを、

### 3-1. 足す前に必ず「そのキーがもう無いか」を調べる ← 2026-09-22 に大事故

`PICTO_ROOT` や `ROOT_NOTES` は 500 件を超える大きな表です。
**表の後ろのほうに、1行にまとめて書かれた行があります。**

```js
  terr:G.voice,awe:G.voice,simil:G.people,vari:G.arrowR,speci:G.box,
  cad:G.arrowR,pli:G.hand,portus:G.box,peri:G.hand,gener:G.people,
```

`grep 'pli:<>'` のような探し方だと、この形が引っかからず「まだ無い」と勘違いします。
**JavaScript は同じキーが2回あると後ろが勝つ**ので、表の先頭に足した絵は
一生表示されない「死んだ記述」になります。実際、pli・pend・voc・dict など22件がこれでした。

足す前と足したあとに、必ず両方これを実行する:

```bash
node check-dup.js     # PICTO_ROOT / ROOT_NOTES / EIKEN_LEVELS などの重複キーを調べる
```

重複が出たら、**後ろのほう（汎用の仮アイコン `G.hand` など）を消して、
ちゃんと描いた絵を残す**こと。

### 3-2. 語源コラム（`ROOT_NOTES`）の書き方 ← 2026-09-22 に全部書き直しになった

**このコラムのいちばんの価値は「知っているカタカナ語が、実は同じ語根だった」という驚きです。**
形だけ3段そろえても、そこが無ければ価値はありません。No.1〜100 期の書き方にそろえてください。

**お手本:**

```js
"fer":{
  title:"フェリーは「運ぶ」船",
  body:"【なぜ】ラテン語 ferre（運ぶ）から。どこへどう運ぶかで意味が変わります。英語の ferry も大もとは同じ根です。\n【身近な日本語】フェリー（運ぶ船）、トランスファー（越えて運ぶ＝乗り継ぎ）、オファー（差し出して運ぶ）。\n【覚え方】フェリーに荷物を載せて運ぶ。offer は相手のほうへ運ぶ＝申し出る、suffer は下で重荷を運ぶ＝苦しむ。"
},
```

| | ○ こう書く | ✕ こう書かない |
|---|---|---|
| title | **カタカナ語を入口にした一文**。「フェリーは「運ぶ」船」「クレームは本当は「叫んで主張する」」 | 「「運ぶ」fer」のような**定型**。これを書いたら不合格 |
| 【なぜ】 | もとの言語と語、そこから**意味がどう枝分かれしたか** | 語源をひとこと書いて終わり |
| 【身近な日本語】 | **実在するカタカナ語を3〜5個、かっこで意味つき**。ゲーム用語・商品名・スポーツ用語でもよい | 「日本語には入っていない」と書いて逃げる |
| 【覚え方】 | カタカナ語を手がかりに、**英単語2〜3語**の理屈をつなげる | 語根の意味をくり返すだけ |

- 本文は3段合わせて **100〜200字**
- **どうしてもカタカナ語が無いときだけ**【身近な英語】に切り替えてよい。
  ただし「無い」と決める前に、ゲーム・スポーツ・IT・商品名・地名まで探すこと。
  実例: thief →「RPGのシーフ」、stir →「理科室のスターラー」、bury →「ハンブルクの -burg」、
  lean →「リーンスタートアップ」、gaze →「ガゼボ」、yawn →「ギャップ(gap)と同じ家族」
- 書いたあと、次で機械的に点検する:

```bash
node -e 'const fs=require("fs");const s=fs.readFileSync("index.html","utf8");
const i=s.indexOf("const ROOT_NOTES={"),j=s.indexOf("\n};",i),b=s.slice(i,j);
const re=/"([^"]+)":\{\s*title:"((?:[^"\\]|\\.)*)",\s*body:"((?:[^"\\]|\\.)*)"\s*\}/g;
const m=[];let x;while((x=re.exec(b)))m.push({k:x[1],t:x[2],y:x[3]});
const f=m.filter(e=>/^「[^」]+」[A-Za-z-]+$/.test(e.t));
const n=m.filter(e=>/日本語[^。]{0,8}入っていない|日本語[^。]{0,8}あまり入って/.test(e.y));
const s3=m.filter(e=>!/【なぜ】/.test(e.y)||!/【覚え方】/.test(e.y)||!/【身近な/.test(e.y));
console.log("件数",m.length,"／定型タイトル",f.map(e=>e.k),"／逃げの記述",n.map(e=>e.k),"／3段欠け",s3.map(e=>e.k));'
```
定型タイトル・逃げの記述・3段欠けが **すべて 0件** になるまで直す。

## 手順5. 音声を作る

音声ツールは `/Users/arutokamiya/Documents/Roots単語アプリ/音声ツール`（`venv/bin/python` を使う）。

  `index.html` の `clipHash()` と同じ計算にすること

- wav で作って `afconvert -f m4af -d aac@22050 -b 64000 -c 1 入力.wav 出力.m4a` で m4a にする
- 保存先は `audio/us/<ハッシュ>.m4a` と `audio/uk/<ハッシュ>.m4a`
- **すでにあるファイルは作り直さない**（存在チェックしてスキップ）
- 目安: 100語で新しい音声は 500〜600文 × 2（米英）。20〜30分かかります

   **コンソールにエラーが出ていないこと**を確認
   （`[BABEL] … exceeds the max of 500KB` は昔から出ている無害な警告。無視してよい）
4. Commit → Push（`main`）。1〜3分で公開URLに反映されます

## 最後に必ず出す「完了チェック表」

作業の最後に次の3つを実行し、**出力をそのまま貼って**報告してください。「たぶん大丈夫」は禁止です。

```bash
node validate.js      # 単語データそのもの（違反0・警告0が目標）
node check-all.js     # つけ忘れ（絵・コラム・英検・音声・番号）。NG 0件が目標
node check-dup.js     # 表の重複キー（重複0が目標）
```

機械が見てくれないのは次の3つです。ここは自分の目で確かめてください。

- **ピクトグラムが何の絵に見えるか**（`preview-picto.js` で画像にし、さらに手順6-2で実画面を見る）
- **語源コラムの中身が「カタカナ語の驚き」になっているか**（手順3-2）
- **語源の説明・例文・和訳の中身**（10語ごとの3回チェックでやる）

## やってはいけないこと

- `audio/` の中身と `<script id="roots-audio-index">` の中身を context に読み込む（巨大です）
- Part α の中身を書き換える／消す／本編に混ぜる。**α は常に全単語の末尾**
- LEAP の番号順を変える／飛ばす／好きな語を選ぶ
- 既存の本編の語を作り直す（綴り・語根は既存データに合わせる）
- 学習データ（localStorage）のキーや形式を、読み替えなしで変える
- ユーザーの代わりにログインする
- 単語データだけ入れて「完了」と報告する（上の完了チェック表を必ず埋める）
- 表にキーを足すとき、重複を調べずに書く（`node check-dup.js`）
- 語源コラムを「「意味」root」という定型タイトルで量産する
- 【身近な日本語】に「日本語には入っていない」と書いて済ませる
- 汎用図形（`G.hand` など）を当てただけで「ピクトグラム済み」と報告する
- `preview-picto.js` の画像だけ見て、アプリの実画面を見ずに完了と言う
- 身に覚えのない差分を、確認せずにコミットする

**先に「何をどう変えるか」を日本語で説明して、確認を取ってから**着手してください。
